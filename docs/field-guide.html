Demo script

~8 minutes

Built for a small live demo with a narrated fallback — every step has something to click and something to say if you'd rather just talk through it. Order matters here, so it's numbered like the run sheet it is. Total run time assumes the console (python -m ethikit serve) and one pre-generated report are already open in tabs before your mentors sit down.

01

Open on the problem, not the tool

45 secframing

Don't lead with code. Lead with the actual hard problem: you can't compress "is this model ethical" into one number, because some fairness definitions are mathematically incompatible with each other — satisfying one can force you to violate another (Kleinberg / Chouldechova). So ethikit refuses to fake a single score.

Say"Ethikit isn't a ranker or a scorer — it's a model-selection and audit tool. It runs real fairness, privacy, and robustness tools against your models on your data, lays out the trade-offs, and leaves an audit trail, instead of pretending there's one 'most ethical' answer."
02

Live: run the console and watch the flow graph

3 minusabilitylive

python -m ethikit serve — tick 3-4 models across families and point out that the command line at the bottom rewrites itself as you click: everything in the UI is a real CLI flag. Press run and narrate the execution graph while it streams: each model is fitted, then every tool lights up under the principle it measures, and results land per principle. When it finishes, change a --weights value and watch the leaderboard re-rank without re-running. Then the radar: each spoke is a principle, each colored polygon is a model, and a bigger polygon is strictly better on that axis. Then point at the leaderboard table and explain the weighted-score column only exists because you supplied weights — the tool never invents them.

Say"Every one of these numbers is 0 to 1, always oriented so 1 is best — even where the underlying metric is naturally 'lower is better,' like an error rate. That normalization happens once, in one place, so nothing downstream has to remember which direction is good."
If the laptop won't cooperate: open the docs site's console — it replays a recorded real run through the same graph, and the results, inspect and model-card tabs all work. Or open the pre-generated report.
03

Live: inspect the maths, then open one Model Card

2 minusabilityarchitecture

First the inspect tab: pick random_forest → membership_inference and show the two histograms — what the attacker sees for training rows vs held-out rows; then aif360 to show the 80%-rule ratio worked through with this run's numbers. Then the model-card tab. Scroll straight to Quantitative Analysis and point at the Mechanism column — this is the single most important thing to show. Every row explains, in one sentence, exactly what computation produced that number: sample sizes, which library ran, which rows were compared. Then scroll to Tool coverage and show that a principle like "safety" has three independent tools corroborating it, and each one is one click away from being swapped or added to.

Say"No score here is a black box. Every single row traces back to a plain-English sentence of what actually happened — and this card also tells you what other registered tools could have scored this same principle, so picking a tool is a visible choice too, not a hidden default."
04

Reveal the architecture (works with or without the laptop)

1.5 minarchitecture / extensibility

This is the point to zoom out and either show README.md's "Extending it" snippet or just describe it verbally — it's short enough to say from memory. Adding an entirely new ethics tool is one file: subclass Evaluator, implement evaluate(), call register(). Nothing else changes — the runner, the scoring, the coverage lookup, and every report discover it automatically.

Say"This has actually been tested three times over three build phases — I've added a SHAP wrapper, a Giskard scanner, and a real adversarial-attack evaluator, and none of them required touching the pipeline. The registry pattern is the whole extensibility story."
05

The rigor flex — real attacks, not toy metrics

1.5 minoptional / if time

If there's time or a pointed question, this is where you show that "ethics evaluation" here means genuinely attacking the model. A hand-off document originally asked for a TensorFlow-Privacy-based membership-inference attack; that package doesn't even install on Python 3.12 anymore, so the actual attack algorithm was implemented natively instead — a real black-box attack (Yeom et al. 2018) that tries to guess which rows a model was trained on. It correctly picked out an overfit random forest as the leakiest model and a plain logistic regression as the safest, on the same data.

Say"When a dependency didn't work, the answer wasn't a weaker proxy quietly relabeled as the real thing — it was implementing the published algorithm directly. Same story for the adversarial-robustness and drift-detection evaluators."
06

Close on what's next

30 secclose

End on the roadmap, not a summary — it signals this is an active project with a plan, not a finished demo. The next phase extends the same registry to deep-learning and LLM evaluators (Captum, Giskard's LLM scan), which is a genuinely bigger architectural jump since the whole pipeline currently assumes tabular sklearn-style models.

Say"Everything so far has been sklearn-shaped. The next open question is what the model context needs to look like once it's a prompt or a tensor instead of a row of numbers."

Architecture at a glance

One dataset, one sweep of models, one battery of evaluators run against each — and every stage after that is generic. This is the diagram to have in your head even if you never put it on a slide.

Pipeline stage reference

What each non-evaluator module actually takes in and hands back. This is the part worth memorizing if you want to answer "how does X actually work" without opening the code.

Runner

In
a Dataset + {name: factory}

Every evaluator call is wrapped in try/except — one broken tool becomes an ERROR:... row, never a crashed sweep.

Scoring

ethikit/scoring/aggregate.py
In
the runner's raw DataFrame
Out
normalize() → 0-1 columns; principle_profile() → model × principle; pareto_front() → non-dominated model list; weighted_score() → opt-in single ranking
Read
Nothing is ranked until you pass weights. No default weighting exists anywhere in this module.

ethikit/coverage.py
In

principle_to_tools(), tool_to_principles(), tool_info() — the reverse of every evaluator's own principle_ids
Read
Answers "which tool should I run for X" and "what does tool Y actually check" — before you run anything.

Reports

ethikit/report/{report,model_card}.py

Read

Repeated CV phase 2

ethikit/benchmark/cv.py
In
RawData, n_splits, n_repeats
Out
the same tidy records, tagged with (repeat, fold) — a distribution per metric, not one point
Read
One split can make a model look best by luck. This is the fix — every score becomes many scores.

Significance phase 2

ethikit/scoring/significance.py
In
a model × sample score matrix (from CV or the meta-benchmark)
Out
Friedman χ², p-value, average ranks, Nemenyi pairwise p-values, a critical-difference diagram PNG
Read
p < 0.05 means the ranking isn't noise. The CD diagram's horizontal bars show which models aren't significantly different.

Meta-benchmark phase 2

ethikit/benchmark/meta.py
In
a model zoo, optionally a list of PMLB dataset names
Out
one run per dataset, concatenated, plus a per-family "best in general" board averaged across all of them
Read
Family-level tendencies become a claim about many datasets, not one anecdote — but this suite is generic (not per-domain, no sensitive attribute), so it speaks to utility, robustness and privacy, not fairness.

The 8 evaluators

3 marked real attack run genuine offensive techniques, not proxies

Every card below is a registered Evaluator subclass. Each one tags its output with a principle, an InspectionTarget (what part of the model/data it actually looks at), and a mechanism string explaining how it decides — shown here as the tool's own general description.

Performance

evaluators/performance.py — axis: utility (not a principle)
predictions

Standard sklearn metrics (accuracy / F1 / ROC-AUC, or R² / RMSE / MAE for regression) computed against the held-out test set.

Read a value
Ordinary metric semantics — accuracy 0.76 means 76% correct. This axis is deliberately excluded from every principle profile so utility never gets silently averaged into ethics.

Fairness

evaluators/fairness.py — principle: fairness
predictionsfairlearn → numpy fallback

Groups predictions by a declared sensitive attribute (e.g. sex) and compares outcome rates across groups — demographic parity + equalized-odds gaps for classification; group MAE/MSE gap for regression.

Read a value
A "gap" metric near 0 means the groups are treated equally by that specific definition; it's flagged higher_is_better=False so normalization flips it correctly.

Explainability

evaluators/explainability.py — principle: explainability
model_internalsSHAP → surrogate-tree fallback

SHAP permutation attributions on a sample of test rows; if SHAP fails, falls back to feature importances from a surrogate decision tree trained to mimic the model.

Read a value
Surrogate fidelity near 1.0 means the explanation is trustworthy — the surrogate tree actually predicts what the real model predicts, not just something plausible-looking.

Robustness (noise)

evaluators/robustness.py — principle: safety
behaviordependency-free

Adds Gaussian noise (σ × per-feature std) to test features, repeated 5×, and measures how often the prediction stays the same.

Read a value
Stability of 0.95 means predictions flipped for only 5% of rows under mild random jitter — a baseline, "does this fall over from ordinary noise" check.

Membership Inference real attack

evaluators/privacy.py — principle: privacy — phase 3
behavior

A genuine black-box attack (Yeom et al. 2018): extracts a confidence/loss feature per row, balances known-member (train) vs known-non-member (test) counts, and fits a cross-validated LogisticRegression attacker to tell them apart. Reports out-of-fold attack AUC and "advantage."

Read a value
advantage = 0.0 means the attack is no better than guessing — no detectable leakage. Higher means an attacker really can tell training rows from held-out rows just by how confidently the model predicts them.
Measured: an unconstrained random_forest (200 trees, no depth cap) scored advantage = 0.325 — clearly memorizing. logistic_regression scored 0.000 on the same data, same split.

Giskard scan

evaluators/giskard_scan.py — principles: fairness, safety
behaviorclassification only

Runs Giskard's automated scanner over a sample of test rows: loss-guided slicing auto-discovers underperforming subgroups (→ fairness); feature perturbation + protected-attribute swaps flag unstable predictions (→ safety). Issues are severity-weighted and summed.

Read a value
giskard_issue_score is higher_is_better=False — it's a weighted count of real issues the scanner actually found, not a normalized rate. 0 means clean.

Adversarial Robustness real attack

evaluators/art_robustness.py — principle: safety — phase 3
behaviorclassification only

A real black-box evasion attack (HopSkipJump, Chen et al. 2019, via the Adversarial Robustness Toolbox) treats the model as a label-only oracle — no gradients, exactly how an outside attacker would query a deployed model — and searches for the smallest perturbation that flips a prediction.

Read a value
adversarial_robustness = 1 − flip rate within a tight query budget. adversarial_perturbation_size (median, among successful flips) is often more informative — larger means the attacker needed a bigger, more detectable change.
On a 4-feature synthetic dataset the attack flips every model within budget (low-dimensional boundaries are easy to cross) — but perturbation size still separates them clearly: 0.235 for random_forest vs 0.764 for gradient_boosting.

Drift Detection real attack

evaluators/drift.py — principle: safety — phase 3
databehavior

Manufactures a synthetic covariate shift, then runs Alibi Detect's real TabularDrift statistical test (per-feature Kolmogorov-Smirnov, Bonferroni-corrected) — checking both whether it correctly flags the shifted set and correctly leaves the unshifted set alone — plus how much the model's own accuracy drops under that shift.

Read a value
drift_detection_score of 1.0 means the statistical test got both calls right. performance_retention_under_drift close to 1.0 means the model degrades gracefully once drift is present.

Reading any output, in general

Four rules cover every number this project ever produces, in every report, chart, and CSV.

1 = always best

normalize() min-max scales every metric to [0,1] and flips the direction when higher_is_better=False, so you never have to remember which way a raw metric points. A radar chart spoke of 1.0 is always the best result in that run, on that principle, full stop.

Scores are relative, not absolute

1.0 means "best among the models actually compared in this run" — not "perfect." Adding a worse model to the sweep can push everyone else's normalized scores up without anything about them changing.

mechanism is never empty

Every EvalResult carries a mandatory mechanism string with this run's real numbers — sample size, backend, groups compared. If a report shows a value with no explanation, that's a bug, not a design choice.

Ordering is opt-in

weighted_score() only ever runs once a human supplies explicit weights. No default weighting scheme exists anywhere — the value judgement has to be visible and attributable to a person.

What's next

Phase 4 — deep learning & LLMs is the only item left on the original roadmap, and it's a bigger jump than phases 1-3: every evaluator so far assumes a sklearn-style tabular model with .fit()/.predict() over numpy arrays. Extending to DL (Captum, a PyTorch/TF adapter) or LLMs (DeepEval/DeepTeam, or Giskard's own LLM scan — already a dependency here) means deciding whether EvalContext grows a non-tabular variant or gets a parallel type entirely. Good, deliberately open question for mentor input.
